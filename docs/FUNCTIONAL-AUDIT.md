## Repairs

- Require real administrator identity and same-origin requests for discovery writes; replace obsolete service-only instructions and add a bounded manual refresh control.
- Preserve reviewed report notes, dates and reviewer references; expose review-status filters and original content. Existing notes discarded by the old implementation cannot be recovered.
- Correct the administrator map deep link, map Back/Forward handling, signed-out inbox destination and account-switch return path.
- Guard stale discussion responses and map resize teardown; remove all organization-navigation listeners on cleanup.
- Prevent capability questions, ambiguous quantities, multiple ordinals, unknown named targets and negated volunteering preferences from producing unrelated chat actions.
- Display overnight event dates and Pacific times consistently; distinguish after-hours closure from an all-day closure.
- Preserve stable legacy reminder IDs on repeated backup imports; merge against current workspace state.
- Show retrieved source notes beside AI source metadata and strengthen instructions against invented logistics.
- Include missing migrations in setup instructions and the civic branch in CI; correct daily-discovery/offline claims.

## Verification limits and operating conditions

- Browser backup import could not finish: the ChatGPT browser extension returned `Not allowed` for local file selection. It requires the extension’s **Allow access to file URLs** setting. The picker opened and parser/merge tests passed, but that is not evidence that the complete browser import flow passed. The user was asked to enable the setting; no consent or setting change is assumed.
- An attempted inventory of all native windows was automatically rejected because it could expose unrelated browser/session metadata. That approach was abandoned; testing stayed in the task’s website tab.
- The linked daily discovery automation is confirmed paused and was not resumed. Manual administrator imports work; uninterrupted daily research requires separately configured and verified service authorization.
- Map access data and wheelchair routes remain community/provider information, not certified step-free navigation. No precise device location was collected for QA.
- AI source links/requirements remain authoritative over generated summaries; a successful inference test does not establish that every generated claim is correct.
- Initial production diagnostics showed canceled conditions/catalog requests during navigation and unsupported robots/sitemap requests, not an established application crash. Public-site runtime and publication checks follow packaging; residents’ moderation queues are not mutated for QA.
